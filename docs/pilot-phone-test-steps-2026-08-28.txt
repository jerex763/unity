UNITY 手机试测步骤：Pastor、签到员、跟进员

完成期限：2026-08-28（周五，Australia/Sydney）
测试网站：https://unity-fictional-demo.onrender.com
预计时长：每人 10–15 分钟

============================================================
所有测试员开始前必读
============================================================

1. 使用自己的手机，以及负责人通过一对一 WhatsApp 私下发送的临时账号。
2. 不要转发账号、发到群里，截图或反馈中也不要包含账号密码。
3. 这个演示环境只能使用虚构数据。只填写负责人提供的虚构活动、姓名、联系方式、
   互动记录和结果。
4. 禁止填写真实姓名、电话、邮箱、微信号、消息内容或牧养信息。如果缺少虚构测试
   数据，请暂停并联系负责人，不要自己编造或使用真实资料。
5. 测试期间不要真的发送 WhatsApp、微信、短信或邮件。
6. 如果看到其他教会的数据、保密关怀内容、超出角色权限的操作，或手机页面无法
   完成操作，请立即停止，只报告角色、页面、时间和脱敏后的问题描述。
7. 完成后退出登录。

建议协作顺序：

Pastor 第一部分 → 签到员 → Pastor 第二部分 → 跟进员


============================================================
清单 1：PASTOR（10–15 分钟）
============================================================

第一部分：签到前

[ ] 1. 用手机打开测试网站，以 Pastor 临时账号登录。
       确认当前 active church 是负责人给出的虚构教会。

[ ] 2. 打开 Events，找到指定虚构活动。
       确认活动名称、日期、地点和报名状态符合负责人提供的信息。

[ ] 3. 在活动卡片中找到“Registrations（人数）”按钮，确认人数看起来合理。
       点击该按钮；报名名单会在同一张活动卡片下方展开，不会进入新页面。
       在展开的“Registrations”区域确认“已报名虚构人员”出现在名单中。

[ ] 4. 打开 People，找到“已存在虚构人员”。
       确认 Pastor 可以查看资料并进入 Edit。
       如果负责人给了指定修改内容，只修改该虚构内容并保存；否则 Cancel，不保存。

[ ] 5. 告诉负责人“Pastor 第一部分完成”，等待签到员完成新访客签到。

第二部分：签到后

[ ] 6. 打开 Follow-ups，找到为“新访客虚构姓名”生成的 first-visit follow-up。
       应只有一个相关新任务，不应出现重复任务。

[ ] 7. 打开任务，点击 Update。
       确认出现覆盖当前页面的弹窗，而不是编辑表单出现在列表下方很远的位置。

[ ] 8. 将 Stage 设为 Assigned（或负责人指定的虚构阶段），将 Assigned to 设为
       指定跟进员，并填写负责人给出的虚构 Due，然后 Save update。

[ ] 9. 重新查看任务，确认 Assigned to、Due 和 Next action 正确。

[ ] 10. 确认整个流程不需要左右横向滚动，然后退出登录。

============================================================
清单 2：签到员 / LEADER（10–15 分钟）
============================================================

[ ] 1. 用手机打开测试网站，以签到员临时账号登录。
       确认当前 active church 和指定活动正确。

[ ] 2. 打开 Events，找到指定活动，点击 Check in 进入专用签到页面。
       活动当天不要把 registration roster 当作签到页面使用。

[ ] 3. 确认默认选中 To check in。
       找到“已报名虚构人员”，确认显示“Registered · Not checked in”。

[ ] 4. 为该人员点击 Check in。
       确认成功提示出现，并且该人员从 To check in 列表消失。

[ ] 5. 在 Find attendee 中输入该人员姓名。
       确认页面自动切换到 All，能找到该人员，并显示
       “Registered · Checked in”。

[ ] 6. 打开 Checked in，确认该人员在其中。
       再打开 Walk-ins，确认临时到访者和已报名人员的分类容易理解。

[ ] 7. 点击 Add walk-in，选择 Existing person。
       搜索负责人指定的“已存在虚构人员”。确认搜索结果只显示足够且经过遮罩的
       识别信息，选择正确人员并完成签到。

[ ] 8. 再次点击 Add walk-in，选择 New visitor。
       只填写负责人提供的虚构姓名和虚构联系方式，添加并确认完成签到。

[ ] 9. 打开 People。
       确认 Leader/签到员账号没有 Create 或 Edit Person 操作。
       不要尝试绕过界面；如果通过任何可用入口成功修改资料，立即停止并报告权限
       问题。

[ ] 10. 确认页面无需左右横向滚动，退出登录，并通知负责人签到流程完成。

============================================================
清单 3：跟进员 / LEADER（10–15 分钟）
============================================================

[ ] 1. 等 Pastor 确认任务已分配后，用手机登录跟进员临时账号。
       确认当前 active church 正确。

[ ] 2. 打开 Follow-ups，选择 My follow-ups。
       确认新分配的虚构任务可见；不应把其他跟进员的任务显示为自己的任务。

[ ] 3. 打开任务，确认虚构人员、Assigned to、Due 和 Next action 与 Pastor 的
       分配一致。

[ ] 4. 点击 Update，确认出现弹窗。
       使用 Cancel 或 X 关闭，确认没有保存；然后再次打开 Update。

[ ] 5. 尝试负责人指定的 WhatsApp 或 WeChat 联系入口。
       确认跳转或 Copy 操作容易理解，但不要发送消息，然后返回 Unity。

[ ] 6. 只添加负责人提供的虚构 interaction。
       确认它出现在 interaction history 中。

[ ] 7. 打开 Update，只填写负责人提供的虚构 Stage、Engagement 和 Outcome，
       按负责人指示关闭该 follow-up，然后 Save update。

[ ] 8. 确认保存后弹窗关闭，更新后的状态和结果可见。
       确认已关闭任务不再显示为 open work。

[ ] 9. 确认页面无需左右横向滚动，然后退出登录。

三位测试员统一反馈问题
============================================================

请通过私下渠道回复。不要包含账号密码、人员联系方式、真实消息内容、牧养信息，
也不要发送包含这些内容的截图。

1. 你是否可以在没有指导的情况下完成任务？
2. 你在哪里犹豫或失去上下文？
3. 对你的角色来说，看到的信息是否过多或过少？
4. 哪一项改动最能改善下一次使用？
5. 关于学生/工作状态、学习领域、行业、未来活动通知或 WhatsApp 群的问题中，
   哪些答案会让你采取实际行动，而不只是“有趣的信息”？

负责人只记录：完成/失败、设备和浏览器、大致用时、脱敏后的流程反馈。
账号停用和虚构数据清理需要另行授权后进行。
